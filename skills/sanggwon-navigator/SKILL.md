# 상권 내비게이터

서울 골목상권 1,650개의 매출·유동인구·개폐업 데이터로 **상권력**을,
서울시 상가임대차 실태조사의 실측 임대료 152개 상권(없으면 한국부동산원 59개로 폴백)과
공실률로 **진입비용**을 각각 판정하고,
기업마당 지원사업 1,500건에서 오늘 신청 가능한 제도를 조건별로 갈라 보여준다.

원칙 두 가지:

- **묻는 건 맨 처음 한 번뿐이다.** 그것도 답하지 않으면 그냥 진행한다.
- **등급을 하나로 합치지 않는다.** "매출이 좋아서 B"인지 "월세가 싸서 B"인지 구분되어야 한다.

리포트는 **동네 → 장사 → 동네×장사 → 지원제도 → 요약** 다섯 부로 나온다.
표마다 "쉽게 말하면" 한 줄이 붙으므로 **그 문장을 그대로 전달하면 된다.**

## Workflow

### Step 0 — 딱 한 번, 맨 처음에 묻는다

지원제도를 **그 사람에게 맞는 것만** 주려면 세 가지를 알아야 한다.
분석을 시작하기 전에 **한 번에 몰아서** 묻는다. 중간에 다시 묻지 않는다.

```
몇 가지만 여쭤볼게요. 답해주시면 딱 맞는 지원제도만 골라드립니다.
① 연령대가 어떻게 되세요? (만 39세 이하인지가 갈림길입니다)
② 첫 창업이신가요, 재도전이신가요?
③ 여성·장애인·보훈 등 해당되는 게 있으신가요? (없으면 넘어가셔도 됩니다)
```

답을 받으면 `--profile` 로 넘긴다. 인식하는 말: `청년` `최초창업` `재도전` `여성` `장애인` `보훈`

```bash
python scripts/make_report.py --region 성수동 --biz 카페 --profile "청년 최초창업"
```

> **답하지 않아도 그대로 진행한다.** 프로필이 없으면 조건별 분기를 전부 보여준다.
> 질문은 하되 **답에 의존하지 않는다.** 그래서 스케줄 자동 실행에서도 멈추지 않는다.

### Step 0-2 — 지역·업종 정규화 (묻지 않는다)

- **지역이 넓으면 그 안에서 가장 좋은 입지를 골라 추천한다.**
  "성수동" → 후보 16곳 중 매출 1위를 기본값으로 잡고, 리포트 상단에 대안 2곳을 함께 제시한다.
  "성수동카페거리" 처럼 콕 집으면 그걸로 간다.
  서울 행정동의 64%가 `성수1가1동` 처럼 쪼개져 있어 스크립트가 어간으로 다시 찾는다.
- **업종**은 `reference/service_codes.yaml` 로 매핑한다. 애매한 업종(피자·마라탕·애견카페 등)은
  **기본값으로 진행하되 대안을 리포트에 표기**한다. 되묻지 않는다.

### Step 1 — 지역과 업종이 둘 다 있는지 확인

이 스킬은 **"어느 동네에서 무슨 장사"** 가 정해졌을 때만 쓴다.
하나가 비어 있으면 그것부터 묻는다 — Step 0 질문과 함께 물어도 된다.

- 지역이 없다 → "서울 어느 동네를 보고 계세요?"
- 업종이 없다 → "무슨 업종을 생각하고 계세요?"

### Step 2 — 실행

```bash
cd <스킬 폴더>
pip install pandas pyarrow pyyaml     # 없을 때만
python scripts/make_report.py --region 성수동 --biz 카페
```

캐시가 없거나 낡았으면 데이터를 자동으로 받는다(약 2분). 사람이 개입하지 않는다.
상권을 직접 고르려면 `--trdar 성수동카페거리`, 네트워크가 막히면 `--skip-policy`.

산출물: `output/<지역>_<업종>_<분기>.md`

#### 인증키 — 사용자에게 묻지 않는다

스크립트는 키를 **환경변수에서 직접 읽는다.** 리포트를 뽑는 데는 앞의 셋이면 된다.

| 환경변수 | 용도 | 없으면 |
|---|---|---|
| `SEOUL_API_KEY` | 서울 상권 데이터 | 진단 불가 |
| `REB_API_KEY` | 부동산원 공실률·권리금 | 진입비용 일부 누락 |
| `BIZINFO_API_KEY` | 기업마당 지원제도 | `--skip-policy` 로 진행 |
| `UPSTAGE_API_KEY` | 임대료 원본 PDF 재파싱 | 리포트 생성에는 불필요 |

- **키가 없다는 에러가 나면 사용자에게 키를 달라고 하지 않는다.**
  대신 *"[설정 > 환경변수]에 `SEOUL_API_KEY` 를 등록해 주세요"* 라고 안내한다.
- **키를 채팅창에 출력하거나 되묻지 않는다.** 대화 기록에 남으면 유출이다.
- 키가 없어도 되는 일은 계속한다. 예를 들어 `--skip-policy` 로 상권 진단만 낼 수 있다.

### Step 3 — 결과 해석 규칙

리포트를 그대로 붙여넣지 말고 **한눈에 표와 처방을 먼저 말한 뒤** 근거를 붙인다.

| 표시 | 뜻 | 전달 방법 |
|---|---|---|
| **표본부족** | 나쁜 상권이 아니라 **점포가 적어 평균을 낼 수 없음** | "판정 불가"로 말한다 |
| **여러 자치구에 걸침** | 같은 이름 동이 여러 구에 있음 (신사동·도곡동) | 어느 구 기준인지 밝히고 좁히는 법을 알려준다 |
| **공실률 높음** | 임차인에겐 **협상 여지** | 나쁜 신호로 말하지 않는다 |
| **빈 조회** | 0이 아니라 **지표 없음** | 0원·최악으로 해석하지 않는다 |

모든 수치에 **기준 분기**를 함께 말한다.

#### ⚠️ 지표를 거꾸로 읽지 않는다

지표 표의 판정 칸에는 **유리 / 보통 / 불리**가 이미 적혀 있다. **그 판정을 그대로 쓴다.**
백분위 숫자만 보고 임의로 해석하지 마라. 특히 아래 둘이 자주 뒤집힌다.

| 지표 | 잘못된 해석 | 올바른 해석 |
|---|---|---|
| **경쟁 밀도 ↓좋음** | "상위 13% → 경쟁자가 적다" ❌ | 판정이 **불리**면 **경쟁이 심하다** |
| **생존 신호** | "−3.0%p → 개업이 더 많다" ❌ | **음수면 폐업이 개업보다 많다** |

경쟁 밀도는 값이 낮을수록 좋은 지표라 백분위를 뒤집어 저장한다.
생존 신호는 `개업률 − 폐업률` 이므로 **부호가 곧 방향**이다.

### Step 4 — 넘기기 전 확인

- [ ] 등급과 함께 **왜 그 등급인지**(기여도 상위 지표 2개)를 말했는가
- [ ] **처방**(노려라/자금력 싸움/저리스크 실험/피하라)을 말했는가
- [ ] 후보 상권이 여러 개면 어느 곳 기준인지 밝혔는가
- [ ] 마감 임박(D-14 이내) 지원제도를 따로 짚었는가
- [ ] 데이터 기준 시점과 출처를 밝혔는가

## 판단 기준은 어디에 있나

숫자와 근거는 전부 파일에 있다. 코드에 하드코딩하지 않는다.

| 무엇 | 어디 |
|---|---|
| 가중치·컷오프·강등 규칙·부담률 구간 | `config/defaults.yaml` |
| 그 숫자를 왜 그렇게 정했는지 | `reference/scoring_rules.md` |
| 업종 매핑과 애매 업종 판단 | `reference/service_codes.yaml` |
| 정책 조건 분기 키워드 | `reference/policy_keywords.yaml` |
| 서울시 상권 ↔ 부동산원 상권 대응 | `reference/rent_districts.yaml` |

## 입력 / 출력

| 인자 | 필수 | 예 |
|---|---|---|
| `--region` | ✓ | 성수동 · 연남동 · 성동구 · "강남 신사동" |
| `--biz` | ✓ | 카페 · 한식음식점 · 치킨집 · 피자 |
| `--trdar` | | 성수동카페거리 (기본값: 매출 1위 상권) |
| `--profile` | | `"청년 최초창업"` — Step 0 답변. 없으면 전체 분기 |
| `--skip-policy` | | 정책 조회 생략 |

출력은 마크다운 리포트 한 장. 5부 구성이다.

| 부 | 내용 |
|---|---|
| 결론 | 종합 등급 · 진입비용 · 처방 · 행동 문장 |
| 1. 이 동네는 어떤 곳인가 | 유동인구 · 상권 흐름 · 임대료 시세 · 공실률 |
| 2. 이 장사는 어떤 장사인가 | 서울 평균 매출 · 원가 구조 · 손익분기 · 권리금 |
| 3. 이 동네에서 이 장사를 하면 | **등급이 여기서 나온다.** 지표 5종 + 손익계산서 + 후보 비교 |
| 4. 받을 수 있는 지원제도 | 내용 · 마감일 · 자격 · 신청 링크 |
| 5. 요약 | 결론 3줄 + 다음에 할 일 |

## 하지 말 것

- **서울 외 지역의 상권 등급을 내지 않는다.** 데이터가 없다. 지원제도만 제공한다.
- **개별 매물이나 공실 위치를 찾아주지 않는다.** 공공데이터에 없다. 상권 단위 공실률만 제공한다.
- **지원제도의 최종 자격을 단정하지 않는다.** 공고 키워드로 분류한 것이므로
  "공고문에서 자격요건을 직접 확인하라"를 반드시 덧붙인다.
- **Step 0 이후에는 되묻지 않는다.** 답을 못 받았으면 그냥 전체 분기로 진행한다.
- **`--refresh` 를 습관적으로 쓰지 않는다.** 서울 API에 일일 호출 한도가 있다.

## 데이터 갱신

세 데이터가 각자 다른 시계로 움직인다.

| 데이터 | 주기 | 어떻게 |
|---|---|---|
| 상권 · 부동산원 | 분기 | 캐시에 기준 분기가 스탬프로 박혀 있고, 최신 분기와 벌어지면 자동 재수집 |
| 임대료 원본 (서울시 실태조사) | 불규칙 | 게시글 번호를 비교해 새 회차가 떴을 때만 재파싱 |
| 지원제도 | 매일 | 캐시하지 않는다. 마감일이 화석이 되면 안 된다 |

```bash
python scripts/fetch_data.py --status      # 상권 캐시 상태
python scripts/rent.py --status            # 부동산원 캐시 상태
python scripts/parse_lease_pdf.py --check  # 새 실태조사 떴는지 확인 (크레딧 0)
python scripts/parse_lease_pdf.py          # 최신본 받아서 재파싱 → CSV 갱신
python scripts/fetch_data.py --refresh     # 분기 강제 갱신
```

**임대료 원본은 주소도 쪽 번호도 코드에 박아두지 않는다.** 자료실에서 그때그때 가장
최신 보고서를 찾고, 표가 있는 쪽은 몇 쪽씩 던져보며 값 범위로 판별한다. 발행 주기가
불규칙해(2015·2017 → 2019 → 2022 → 2023) 갱신 시점을 예측할 수 없기 때문이다.
지금 쓰는 회차는 `reference/seoul_lease_source.json` 에, 결과는
`reference/seoul_lease_districts.csv` 에 있다. **확인은 무료, 파싱만 크레딧을 쓴다.**
