# 상권 내비게이터

서울 골목상권 1,650개의 매출·유동인구·개폐업 데이터로 **상권력**을,
서울시 상가임대차 실태조사의 실측 임대료 152개 상권(없으면 한국부동산원 59개로 폴백)과
공실률로 **진입비용**을 각각 판정하고,
기업마당 지원사업 1,500건에서 오늘 신청 가능한 제도를 조건별로 갈라 보여준다.

원칙 두 가지:

- **묻는 건 맨 처음 한 번뿐이다.** 그것도 답하지 않으면 그냥 진행한다.
- **등급을 하나로 합치지 않는다.** "매출이 좋아서 B"인지 "월세가 싸서 B"인지 구분되어야 한다.

리포트는 **동네 → 장사 → 동네×장사 → 지원제도 → 요약** 다섯 부로 나온다.
표마다 "쉽게 말하면" 한 줄이 붙으므로 **그 문장을 그대로 전달하면 된다.**

## Workflow

> ## ⛔ 가장 중요한 규칙 — 리포트는 파일로 준다
> 스크립트는 **`.md` 와 `.html` 두 개**를 만든다.
> **`.html` 파일을 사용자에게 건네고, 채팅에는 아래 네 줄만 쓴다.**
>
> ```
> 진단이 끝났습니다. 리포트를 첨부했습니다.  ← HTML 파일 공유
>
> · 어디    <상권명> (<상권구분>, <자치구>)
> · 등급    <등급> — 서울 <업종> 상권 <N>곳 중 상위 <M>%
> · 비용    <진입비용> — 임대료 부담률 <X>%
> · 처방    <처방 한 줄>
>
> 리포트에 5부로 나눠 담았습니다 — 동네 / 장사 / 둘을 합치면 / 지원제도 / 요약.
> 보시다가 모르는 부분 있으면 말씀해 주세요. 그 부분만 풀어서 설명해 드립니다.
> ```
>
> **리포트 본문을 채팅에 옮기지 마라.** 요약하지도, 다시 쓰지도, 자기 제목을
> 새로 만들지도 마라. 표·신청 링크·💡 문장은 파일 안에 이미 다 있다.
> 채팅에 옮기려 하면 반드시 무언가(특히 **신청 URL**)를 잃는다.
>
> ❌ `📊 결론 한눈에` `🔑 꼭 알아둘 핵심 3가지` `✅ 그런데 대안이 있어요`
>
> 사용자가 **"이게 무슨 뜻이야"** 라고 물으면 그때 그 대목만 설명한다.

### Step 0 — 맨 처음에 선택형 질문 세 개

지원제도를 **그 사람에게 맞는 것만** 주려면 세 가지를 알아야 한다.
분석을 시작하기 **전에** 다 묻는다. 분석이 시작된 뒤에는 다시 묻지 않는다.

#### ⛔ 글로 묻지 마라 — 선택형 질문 도구를 써라

`① 연령대 1) … 2) …` 를 **채팅에 글로 쓰지 않는다.** 사용자가 숫자를 타이핑하게
만들지 마라. **선택지를 눌러서 고르게** 한다. (Timely 는 `ask_user_form`)

**세 질문을 한 번에 세팅해서 연달아 나오게 한다.** 하나씩 따로 띄우지 마라.
사용자는 클릭 세 번이면 끝난다.

| # | 질문 | 선택지 | 복수 선택 |
|---|---|---|---|
| 1 | 연령대가 어떻게 되세요? | `20·30대 (만 39세 이하)` · `40대` · `50대` · `60대 이상` | ✗ |
| 2 | 창업 경험은 어떻게 되세요? | `첫 창업` · `재도전` · `이미 운영 중` | ✗ |
| 3 | 해당되는 게 있으세요? | `없음` · `여성` · `장애인` · `보훈대상자` | ✓ |

선택지마다 **왜 묻는지** 한 줄을 붙인다. 고르는 사람이 이유를 알아야 한다.

```
20·30대 (만 39세 이하)  →  청년 창업 지원제도 대상입니다. 청년전용 자금·교육 공고가 추가로 붙습니다.
40대 / 50대 / 60대 이상  →  청년 전용 제도는 빠집니다. 중장년 대상 사업이 있으면 함께 봅니다.
첫 창업                  →  초기 창업자 전용 교육·자금 공고가 붙습니다.
재도전                   →  재도전 특화 제도(희망리턴패키지 등)가 붙습니다.
이미 운영 중             →  창업 전용 제도는 빼고 경영안정 중심으로 봅니다.
없음                     →  아래 어느 것도 해당하지 않으면 이것만 고르세요.
여성 / 장애인 / 보훈대상자 →  해당 대상 전용 제도가 함께 검색됩니다.
```

#### 고른 답을 번호로 옮긴다

| 고른 것 | 자리 | 값 |
|---|---|---|
| 20·30대 (만 39세 이하) | 1번째 | `1` |
| 40대 · 50대 · 60대 이상 | 1번째 | `2` |
| 첫 창업 / 재도전 / 이미 운영 중 | 2번째 | `1` / `2` / `3` |
| 없음 / 여성 / 장애인 / 보훈대상자 | 3번째 | `0` / `1` / `2` / `3` — 복수면 붙여서 `13` |

```bash
# 20·30대 · 첫 창업 · 해당없음
python3 scripts/make_report.py --region 성수동 --biz 카페 --profile "1 1 0"
```

- 사용자가 그냥 말로 답하면(`"39세 첫 창업이요"`) `--profile "청년 최초창업"` 도 받는다.
- **답을 못 받으면 다시 묻지 말고** `--profile` 없이 진행한다.
  조건별 분기를 전부 보여주므로 리포트는 그대로 완결된다.
  질문은 하되 **답에 의존하지 않는다.** 그래서 스케줄 자동 실행에서도 멈추지 않는다.

### Step 0-2 — 지역·업종 정규화 (묻지 않는다)

- **지역이 넓으면 그 안에서 가장 좋은 입지를 골라 추천한다.**
  "성수동" → 후보 16곳 중 매출 1위를 기본값으로 잡고, 리포트 상단에 대안 2곳을 함께 제시한다.
  "성수동카페거리" 처럼 콕 집으면 그걸로 간다.
  서울 행정동의 64%가 `성수1가1동` 처럼 쪼개져 있어 스크립트가 어간으로 다시 찾는다.
- **업종**은 `reference/service_codes.yaml` 로 매핑한다. 애매한 업종(피자·마라탕·애견카페 등)은
  **기본값으로 진행하되 대안을 리포트에 표기**한다. 되묻지 않는다.

### Step 1 — 지역과 업종이 둘 다 있는지 확인

이 스킬은 **"어느 동네에서 무슨 장사"** 가 정해졌을 때만 쓴다.
하나가 비어 있으면 그것부터 묻는다 — Step 0 질문과 함께 물어도 된다.

- 지역이 없다 → "서울 어느 동네를 보고 계세요?"
- 업종이 없다 → "무슨 업종을 생각하고 계세요?"

### Step 2 — 실행

```bash
cd <스킬 폴더>

# ⚠️ pip 가 아니라 python3 -m pip 로 깐다. 스크립트를 돌릴 파이썬에 그대로 넣기 위해서다.
python3 -m pip install pandas pyarrow pyyaml \
  || python3 -m pip install --break-system-packages pandas pyarrow pyyaml

python3 scripts/make_report.py --region 성수동 --biz 카페
```

> **`pip install` 만 쓰면 안 된다.** `pip` 와 `python3` 가 서로 다른 파이썬을 가리키는
> 환경이 있다. 설치는 성공했는데 실행하면 `ModuleNotFoundError: No module named 'yaml'`
> 이 나고, 없는 모듈을 하나씩 다시 까느라 시간을 버린다.
> **깔 때와 돌릴 때 같은 이름(`python3`)을 쓴다.**
>
> 한 번에 확인하려면:
> ```bash
> python3 -c "import pandas, pyarrow, yaml; print('ok')"
> ```
> `ok` 가 나오면 설치 끝. 아니면 위 설치 줄을 다시 돌린다.

#### 첫 실행이 2분 넘게 걸리면 — 동봉 캐시를 못 깐 것이다

스킬 안에 `bundled-cache/` 가 들어 있어 **첫 실행도 API 수집 없이 바로 나온다.**
2~3분씩 걸린다면 그게 안 깔린 것이니 먼저 확인한다.

```bash
ls bundled-cache/ | head          # 파일 10개가 보여야 한다
python3 scripts/fetch_data.py --status
```

`--status` 가 **기준 분기 20261** 을 보여주면 정상이다. 캐시를 못 깔면
`⚠️ 동봉 캐시를 깔지 못했습니다` 가 찍히니 그 메시지를 그대로 사용자에게 알린다.

캐시가 없거나 낡았으면 데이터를 자동으로 받는다. 사람이 개입하지 않는다.
상권을 직접 고르려면 `--trdar 성수동카페거리`, 네트워크가 막히면 `--skip-policy`.

#### ⏱️ 첫 실행이 타임아웃되면 — **그냥 다시 실행한다**

첫 수집은 20만 행이라 실행 환경의 명령 타임아웃(예: 180초)에 걸릴 수 있다.
**이건 실패가 아니다.** 분기 하나를 받을 때마다 저장하므로 받은 만큼은 남는다.

```bash
python3 scripts/fetch_data.py     # 타임아웃 → 다시 실행 → 이어받음 (보통 2~3회)
python3 scripts/fetch_data.py --status
```

`--status` 가 **미완료**라고 하면 같은 명령을 다시 친다. 이미 받은 것은 건너뛰므로
매번 빨라지고, 다 받으면 0초에 끝난다. 처음부터 다시 받지 않는다.
**타임아웃을 에러로 보고하지 말고 재실행하라.**

산출물 **두 개** — `output/<지역>_<업종>_<분기>.md` 와 같은 이름의 `.html`
**사용자에게는 `.html` 을 건넨다.**

#### 인증키 — 사용자에게 묻지 않는다

스크립트는 키를 **환경변수에서 직접 읽는다.** 리포트를 뽑는 데는 앞의 셋이면 된다.

| 환경변수 | 용도 | 없으면 |
|---|---|---|
| `SEOUL_API_KEY` | 서울 상권 데이터 | 진단 불가 |
| `REB_API_KEY` | 부동산원 공실률·권리금 | 진입비용 일부 누락 |
| `BIZINFO_API_KEY` | 기업마당 지원제도 | `--skip-policy` 로 진행 |
| `UPSTAGE_API_KEY` | 임대료 원본 PDF 재파싱 | 리포트 생성에는 불필요 |

- **키가 없다는 에러가 나면 사용자에게 키를 달라고 하지 않는다.**
  대신 *"[설정 > 환경변수]에 `SEOUL_API_KEY` 를 등록해 주세요"* 라고 안내한다.
- **키를 채팅창에 출력하거나 되묻지 않는다.** 대화 기록에 남으면 유출이다.
- 키가 없어도 되는 일은 계속한다. 예를 들어 `--skip-policy` 로 상권 진단만 낼 수 있다.

### Step 3 — 파일을 건네고, 물어보면 그때 설명한다

리포트는 **`output/` 에 `.md` 와 `.html` 두 개**가 생긴다. **HTML 을 공유한다.**
채팅에는 결론 네 줄과 "모르는 부분 물어보세요"만 쓴다 (맨 위 규칙 참조).

리포트 안은 이렇게 짜여 있다. 사용자가 물으면 해당 부를 찾아 설명한다.

| 부 | 제목 | 반드시 살릴 것 |
|---|---|---|
| — | **결론** | 등급 · 진입비용 · 처방 표 |
| **1** | **이 동네는 어떤 곳인가** | 표 + 💡 쉽게 말하면 |
| **2** | **이 장사는 어떤 장사인가** | 표 + 💡 쉽게 말하면 |
| **3** | **이 동네에서 이 장사를 하면** | 지표표 + 손익계산서 + 💡 쉽게 말하면 + 후보 상권 비교 |
| **4** | **받을 수 있는 지원제도** | 제도마다 내용 · 마감 · **자격** · **신청 링크** |
| **5** | **요약** | 결론 3줄 + 다음에 할 일 |

설명할 때 아래 해석 규칙을 지킨다.

| 표시 | 뜻 | 전달 방법 |
|---|---|---|
| **표본부족** | 나쁜 상권이 아니라 **점포가 적어 평균을 낼 수 없음** | "판정 불가"로 말한다 |
| **여러 자치구에 걸침** | 같은 이름 동이 여러 구에 있음 (신사동·도곡동) | 어느 구 기준인지 밝히고 좁히는 법을 알려준다 |
| **공실률 높음** | 임차인에겐 **협상 여지** | 나쁜 신호로 말하지 않는다 |
| **빈 조회** | 0이 아니라 **지표 없음** | 0원·최악으로 해석하지 않는다 |

모든 수치에 **기준 분기**를 함께 말한다.

#### ⚠️ 지표를 거꾸로 읽지 않는다

지표 표의 판정 칸에는 **유리 / 보통 / 불리**가 이미 적혀 있다. **그 판정을 그대로 쓴다.**
백분위 숫자만 보고 임의로 해석하지 마라. 특히 아래 둘이 자주 뒤집힌다.

| 지표 | 잘못된 해석 | 올바른 해석 |
|---|---|---|
| **경쟁 밀도 ↓좋음** | "상위 13% → 경쟁자가 적다" ❌ | 판정이 **불리**면 **경쟁이 심하다** |
| **생존 신호** | "−3.0%p → 개업이 더 많다" ❌ | **음수면 폐업이 개업보다 많다** |

경쟁 밀도는 값이 낮을수록 좋은 지표라 백분위를 뒤집어 저장한다.
생존 신호는 `개업률 − 폐업률` 이므로 **부호가 곧 방향**이다.

### Step 4 — 넘기기 전 확인

- [ ] 등급과 함께 **왜 그 등급인지**(기여도 상위 지표 2개)를 말했는가
- [ ] **처방**(노려라/자금력 싸움/저리스크 실험/피하라)을 말했는가
- [ ] 후보 상권이 여러 개면 어느 곳 기준인지 밝혔는가

## 판단 기준은 어디에 있나

숫자와 근거는 전부 파일에 있다. 코드에 하드코딩하지 않는다.

| 무엇 | 어디 |
|---|---|
| 가중치·컷오프·강등 규칙·부담률 구간 | `config/defaults.yaml` |
| 그 숫자를 왜 그렇게 정했는지 | `reference/scoring_rules.md` |
| 업종 매핑과 애매 업종 판단 | `reference/service_codes.yaml` |
| 정책 조건 분기 키워드 | `reference/policy_keywords.yaml` |
| 서울시 상권 ↔ 부동산원 상권 대응 | `reference/rent_districts.yaml` |

## 입력 / 출력

| 인자 | 필수 | 예 |
|---|---|---|
| `--region` | ✓ | 성수동 · 연남동 · 성동구 · "강남 신사동" |
| `--biz` | ✓ | 카페 · 한식음식점 · 치킨집 · 피자 |
| `--trdar` | | 성수동카페거리 (기본값: 매출 1위 상권) |
| `--profile` | | `"1 1 0"` 번호 또는 `"청년 최초창업"` 말. 없으면 전체 분기 |
| `--skip-policy` | | 정책 조회 생략 |
| `--no-html` | | HTML 을 만들지 않는다 (기본은 만든다) |

출력은 리포트 한 장. **마크다운(.md)과 HTML(.html)** 두 형식으로 나온다.
HTML 은 한 파일로 완결되어(외부 로드 없음) 바로 열린다. 5부 구성이다.

| 부 | 내용 |
|---|---|
| 결론 | 종합 등급 · 진입비용 · 처방 · 행동 문장 |
| 1. 이 동네는 어떤 곳인가 | 유동인구 · 상권 흐름 · 임대료 시세 · 공실률 |
| 2. 이 장사는 어떤 장사인가 | 서울 평균 매출 · 원가 구조 · 손익분기 · 권리금 |
| 3. 이 동네에서 이 장사를 하면 | **등급이 여기서 나온다.** 지표 5종 + 손익계산서 + 후보 비교 |
| 4. 받을 수 있는 지원제도 | 내용 · 마감일 · 자격 · 신청 링크 |
| 5. 요약 | 결론 3줄 + 다음에 할 일 |

## 하지 말 것

- **서울 외 지역의 상권 등급을 내지 않는다.** 데이터가 없다. 지원제도만 제공한다.
- **개별 매물이나 공실 위치를 찾아주지 않는다.** 공공데이터에 없다. 상권 단위 공실률만 제공한다.
- **지원제도의 최종 자격을 단정하지 않는다.** 공고 키워드로 분류한 것이므로
  "공고문에서 자격요건을 직접 확인하라"를 반드시 덧붙인다.
- **Step 0 이후에는 되묻지 않는다.** 답을 못 받았으면 그냥 전체 분기로 진행한다.
- **`--refresh` 를 습관적으로 쓰지 않는다.** 서울 API에 일일 호출 한도가 있다.

## 쓰는 도구

| 도구 | 어디에 |
|---|---|
| **Upstage Document Parse** | ① 서울시 상가임대차 실태조사 스캔 PDF(전 쪽 이미지, 텍스트 0자)에서 145개 주요상권 임대료 표 추출 — 표가 몇 쪽에 있는지도 이걸로 찾는다 ② 지원제도 공고문 중 **이미지·스캔본**에서 지원자격 추출 |
| **Upstage Solar** (`solar-pro2`) | ① 임대료 표는 5블록 병합이라 셀 정렬이 깨진다. 이를 JSON 으로 정형화 ② 공고문 본문에서 지원자격 조건만 골라 2~4줄로 정리 |

**지원자격은 API 에 없어서 공고문을 연다.** 기업마당 API 는 공고명·마감일·신청링크는
주지만 자격 필드가 없다(요약 200~370자에도 없다). 대신 첨부 파일 주소를 함께 주므로
그 문서를 읽는다. 첨부가 PDF 면 `pypdf` 로 공짜로 읽고, **이미지·스캔·docx 는
Document Parse 로만 읽힌다**(전체의 약 13%). hwp 는 지원 형식이 아니라 건너뛴다.

```bash
python3 scripts/policy_detail.py --district 성동구 --top 3
```

자세히 보여줄 **상위 3건에만**, 각 **앞 5쪽만** 본다. 공고 ID로 캐시하므로 같은 공고를
두 번 열지 않는다. 어느 단계에서 실패하든 조용히 넘어가고 "공고문에서 직접 확인" 안내가
그대로 남는다.

## 데이터 갱신

세 데이터가 각자 다른 시계로 움직인다.

| 데이터 | 주기 | 어떻게 |
|---|---|---|
| 상권 · 부동산원 | 분기 | 캐시에 기준 분기가 스탬프로 박혀 있고, 최신 분기와 벌어지면 자동 재수집 |
| 임대료 원본 (서울시 실태조사) | 불규칙 | 게시글 번호를 비교해 새 회차가 떴을 때만 재파싱 |
| 지원제도 | 매일 | 캐시하지 않는다. 마감일이 화석이 되면 안 된다 |

```bash
python3 scripts/fetch_data.py --status      # 상권 캐시 상태
python3 scripts/rent.py --status            # 부동산원 캐시 상태
python3 scripts/parse_lease_pdf.py --check  # 새 실태조사 떴는지 확인 (크레딧 0)
python3 scripts/parse_lease_pdf.py          # 최신본 받아서 재파싱 → CSV 갱신
python3 scripts/fetch_data.py --refresh     # 분기 강제 갱신
```

**임대료 원본은 주소도 쪽 번호도 코드에 박아두지 않는다.** 자료실에서 그때그때 가장
최신 보고서를 찾고, 표가 있는 쪽은 몇 쪽씩 던져보며 값 범위로 판별한다. 발행 주기가
불규칙해(2015·2017 → 2019 → 2022 → 2023) 갱신 시점을 예측할 수 없기 때문이다.
지금 쓰는 회차는 `reference/seoul_lease_source.json` 에, 결과는
`reference/seoul_lease_districts.csv` 에 있다. **확인은 무료, 파싱만 크레딧을 쓴다.**
